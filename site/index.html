How It Works

Fast, zero-config local discovery without port scanning or external accounts.

  1. 1

    Process & CSRF Discovery

    Locates the active language_server process and reads its session CSRF token from CLI flags or environment variables.

  2. 2

    Sub-Millisecond Port Lookup

    Uses lsof (with netstat fallback) to find the exact listening TCP port for the discovered PID.

  3. 3

    Local Connect-RPC

    Queries RetrieveUserQuotaSummary on 127.0.0.1 over HTTP/HTTPS with the CSRF header.

  4. 4

    Shared Store & Widget Sync

    Saves snapshots to Application Support and triggers WidgetCenter.reloadAllTimelines() without TCC prompts.

Frequently Asked Questions

macOS says "Antigravity Quota" cannot be opened because the developer cannot be verified

Current official releases (v1.4.0+) are signed with an Apple Developer ID certificate and notarized by Apple, so they open without Gatekeeper warnings. For older historical releases (v1.3.1 and earlier) or self-built ad-hoc binaries, right-click Antigravity Quota.app in /Applications, select Open, and confirm—or run xattr -cr "/Applications/Antigravity Quota.app" in Terminal.

Why does the menu bar show "Waiting for Antigravity" or "Offline"?

Antigravity Quota reads quota directly from the running Google Antigravity language_server process. Make sure Google Antigravity is open locally—or enable Remote SSH under Settings > Remote if you run it on another machine.

Why does a 100% full quota show "Unused" instead of a countdown?

Antigravity's 5-hour and weekly limits use a rolling window over consumed quota. When 100% of a bucket is intact, the server shifts the candidate reset timestamp forward on each request, so Antigravity Quota displays "Unused" until consumption begins.

Does it collect telemetry or require API keys?

No. It runs 100% locally against 127.0.0.1 (or your configured SSH host), stores zero API keys or credentials, and sends zero telemetry or analytics.

Can I monitor Antigravity running on another Mac?

Yes. Set up key-based SSH authentication (BatchMode=yes) to the target machine, then open Settings > Remote, enable Remote SSH Query, enter your user@hostname or ~/.ssh/config alias, and click Test Connection.
